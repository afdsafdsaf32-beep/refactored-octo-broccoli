# Подключение по USB (в дополнение к WiFi)

Приложение всегда говорит по обычным TCP-сокетам (порты 9001 — видео, 9002 —
данные гироскопа). Поэтому кабель — это не отдельный протокол, а просто ещё
один способ доставить те же TCP-порты до телефона: через `usbmuxd`, тот же
механизм, которым пользуется Xcode/iTunes для связи с iPhone по кабелю.

## Идея

1. iPhone физически подключён к ПК по USB.
2. На ПК поднимается процесс `iproxy` (утилита из `libimobiledevice`),
   который создаёт локальный TCP-туннель: всё, что приходит на
   `127.0.0.1:9001` на **телефоне**, на самом деле проксируется на
   `127.0.0.1:9001` на **ПК** через USB, и наоборот.
3. Приложение на телефоне просто подключается к `127.0.0.1` — ему всё равно,
   что трафик на самом деле идёт по кабелю, а не по WiFi.

Так как логика приложения не завязана на транспорт, весь код из
`ios-client/PhoneVR` работает без изменений что по WiFi (адрес = LAN IP ПК),
что по USB (адрес = `127.0.0.1`).

## Установка на Windows (ПК)

```powershell
# libimobiledevice для Windows (например, через imazing / usbmuxd драйвер,
# либо через пакет "libimobiledevice-windows" с GitHub)
iproxy 9001 9001   # видео
iproxy 9002 9002   # управление гироскопом
```

`iproxy` умеет пробрасывать несколько портов одной командой в новых версиях:
`iproxy 9001:9001 9002:9002`.

## Что вводить в приложении

- **WiFi:** IP-адрес ПК в локальной сети, например `192.168.1.100`.
- **USB:** `127.0.0.1` (или `localhost`) — так как порт проброшен через
  кабель на сам телефон.

## Автоопределение (следующий шаг)

Пока выбор WiFi/USB ручной — вводится IP. Можно добавить автоматическое
определение: если `iproxy`-туннель поднят, `127.0.0.1:9001` будет доступен
даже без WiFi, так что приложение может сначала пробовать USB
(`127.0.0.1`), и при неудаче — fallback на сохранённый WiFi IP.
