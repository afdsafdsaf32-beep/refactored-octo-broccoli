# SteamVR-режим: протокол PhoneVR

`ios-client/PhoneVR/PVRProtocol.swift` и `PVRSteamVRClient.swift` реализуют
протокол открытого драйвера **PhoneVR** (github.com/PhoneVR-Developers/PhoneVR,
`code/windows/PhoneVR` — OpenVR-driver, и `code/common` — общая часть).
Он вычитан напрямую из их исходников (`PVRSocketUtils.cpp`, `PVRSockets.cpp`,
`driver.cpp`), Android там есть, iOS — нет, поэтому наш клиент реализует ту же
проводную схему с нуля на Swift, чтобы подключаться к их **уже готовому и
бесплатному** OpenVR-драйверу — вместо того, чтобы писать свой драйвер.

## Как это работает

Три канала, три порта по умолчанию (`PVRFileManager.h`):

| Канал | Порт | Транспорт | Направление |
|---|---|---|---|
| Pairing/Control | 33333 | UDP → затем TCP | сначала UDP-анонс телефон→ПК, затем ПК сам подключается к телефону по TCP |
| Video | 15243 | TCP | телефон подключается к ПК |
| Pose | 51423 | UDP | телефон → ПК, непрерывно |

### Последовательность

1. Телефон шлёт на `PC_IP:33333` UDP-пакет `"pvr" + PAIR_HMD(0) + version(4 байта)`.
2. Драйвер на ПК получает его и **сам открывает TCP-соединение к телефону**
   на тот же порт 33333 — поэтому на телефоне обязательно должен уже слушать
   TCP-сервер на этом порту (`PVRSteamVRClient` поднимает `NWListener`).
3. ПК присылает по TCP-каналу кадр `PAIR_ACCEPT`.
4. Телефон отвечает `ADDITIONAL_DATA`: ширина/высота рендер-таргета, raw-FOV
   (left/bottom/right/top в тангенсах половинных углов) и IPD.
5. ПК присылает `HEADER_NALS` — это SPS/PPS для H.264 декодера.
6. Телефон подключается к `PC_IP:15243` (TCP) и построчно читает: 64-байтный
   заголовок кадра (pts, кватернион, размер NAL, диагностические FPS/задержки,
   таймстемп) + сам H.264 NAL (Annex-B).
7. Телефон непрерывно шлёт на `PC_IP:51423` (UDP) пакеты с кватернионом
   ориентации головы (формат: 4 float кватерниона + 3 float заглушки под
   акселерометр + int64 таймстемп).

Формат всех бинарных структур (порядок полей, little-endian) в точности
повторяет C++-структуры сервера — байт в байт, без изменений.

## Как использовать

1. Собери и установи PhoneVR OpenVR driver на ПК из их репозитория
   (`code/windows/PhoneVR`, Visual Studio) и зарегистрируй его в SteamVR
   (`vrpathreg`).
2. Запусти SteamVR.
3. В нашем iOS-приложении выбери режим **"SteamVR (PhoneVR driver)"**,
   введи IP ПК, нажми Connect.

## Известные ограничения / что дальше

- **FOV/IPD** в `PVRSteamVRClient.sendAdditionalData()` — заглушка (~100°
  симметрично, IPD 0.063 м). Для реального Cardboard-держателя стоит
  подставить точные значения линз.
- **Синхронизация времени для позы** приблизительная: `posePacket`
  использует `DispatchTime.now().uptimeNanoseconds` телефона, а ПК сравнивает
  его со своим `std::chrono::steady_clock` — это разные монотонные часы на
  разных устройствах, так что `poseTimeOffset` на стороне ПК будет не совсем
  точным. На базовую работу это не влияет, но может слегка портить
  предсказание позы (reprojection) при движении.
- Позиционное отслеживание (6DoF) не реализовано — только поворот головы
  (3DoF, как обычный Cardboard). Полноценный 6DoF потребовал бы ARKit
  visual-inertial tracking и изменения протокола на стороне ПК-драйвера.
- Не тестировалось на реальном устройстве/SteamVR — код написан по чтению
  исходников PC-стороны протокола, а не проверен вживую. Первый прогон нужно
  делать с логами включёнными на обеих сторонах.
